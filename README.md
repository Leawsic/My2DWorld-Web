# My2DWorld Web

这是 Python + pygame 版 2D 沙盒游戏的浏览器迁移版本。浏览器使用 Canvas 2D 渲染游戏，本地 Node 服务负责账号、设置、世界列表和世界存档文件。

## 运行项目

```bash
npm install
npm run dev
```

在浏览器打开 `http://127.0.0.1:5173`。

如需使用其他端口：

```bat
set PORT=5174
npm run dev
```

生产构建验证：

```bash
npm run build
```

开发时必须执行 `npm run dev`，不能直接执行 `vite`。`server.mjs` 会先提供基于文件的 `/api/*` 接口，再将其他请求交给 Vite 处理。

默认账号：`steve` / `1234asdf`。登录界面不再预填账号名，点击"使用默认账号"登录前会弹窗确认。

## 项目结构

```text
web/
├── server.mjs                 本地 HTTP 服务和 Vite 中间件宿主
├── src/
│   ├── main.ts                界面状态、输入、Canvas 主循环、HUD、聊天
│   ├── i18n.ts                集中的中英文显示文案
│   ├── registry.ts             Blocks/GameModes 统一注册表入口
│   ├── core/
│   │   ├── world.ts           World/Chunk 对象、地形、区块和方块状态
│   │   ├── block.ts           Block 运行时对象和 BlockDefinition
│   │   ├── player.ts          Player 对象、物理、碰撞、二段跳和飞行
│   │   ├── physics.ts         共享刚体移动与地面碰撞
│   │   ├── entity.ts          实体/Mob、AI、召唤与碰撞箱
│   │   ├── features.ts / structures.ts  地形特征（树、仙人掌、建筑等）
│   │   ├── particles.ts       从纹理采样的方块破坏粒子
│   │   ├── hitboxes.ts        服务端碰撞箱配置加载与插件覆盖
│   │   ├── skeleton.ts / anim.ts / animations.ts  字符动画与 .myanim 解析渲染
│   │   ├── items.ts           物品（工具）注册表与纯规则：挖掘速度/伤害/耐久/堆叠上限
│   │   ├── tick.ts            客户端 tick 速率（游戏速度）的换算与帧内子步拆分
│   │   ├── pixels.ts          设备像素对齐（消除非整数 dpr 下相邻色块的抗锯齿接缝）
│   │   ├── storage.ts         同步本地 API 客户端
│   │   └── types.ts           稳定的游戏数据类型
│   ├── modes/                 创造、生存、冒险和旁观模式实现
│   └── plugins/api.ts         插件扩展注册表与生命周期 API
├── public/
│   ├── assets/                从 Python 版迁移的纹理、字体和背景（物品贴图在 assets/items/）
│   ├── animations/            .myanim 字符动画文件（/api/animations 清单）
│   ├── items/items.json       物品（镐/斧/剑/锹/锄）配置：挖掘速度、伤害、耐久（/api/items）
│   ├── blocks/blocks.json     方块定义：硬度与对口工具类别（/api/blocks）
│   └── hitboxes/              按分类的碰撞箱 JSON（/api/hitboxes）
├── plugins/                   自动扫描并加载的外部 ESM 插件
└── run/                       由 server.mjs 创建的本地运行数据
    ├── accounts/
    ├── config/
    ├── logs/
    └── worlds/
```

`main.ts` 负责浏览器专属逻辑；可复用的游戏规则放在 `core/`；新游戏模式放在 `modes/`。游戏对象统一从 `registry.ts` 的 `Blocks`、`GameModes` 和 `Registries` 获取；插件应通过 `plugins/api.ts` 扩展，不应直接依赖游戏内部状态。

核心运行时按对象职责组织：`Block` 表示世界中的一个方块实例，持有类型定义和坐标；`Chunk` 管理 16 格宽的区块与区块内方块；`World` 管理区块流送、世界修改和存档转换；`Player` 管理位置、状态和移动物理；`GameMode` 只编排模式规则。运行时使用对象，存档仍只保存方块 ID、坐标和基础数据，避免把类实例直接序列化。

## 世界高度

世界采用类似现代 Minecraft 的纵向空间：

| 数值 | 说明 |
| --- | --- |
| 建造高度上限 `Y=320` | 最高可放置方块的 Y 坐标为 `319` |
| 最低点 `Y=-64` | 底部两层为基岩（`-64`、`-63`），之下为虚空 |
| 深板岩 | `Y≈0` 以下过渡为深板岩及其矿石变种 |

各群系地表高度：海洋 48–54、河流 56–62、平原 64–70、森林 64–70、沙漠 66–70、雪原 88–100、山地最高可达 130–190+（`Y≥148` 会覆盖积雪帽）。群系为多尺度生成：海洋由极低频大陆噪声控制，可延伸 5000+ 格；河流是约 50–100 格宽的沙质窄带；气候带（平原/森林/沙漠/雪原/山地）跨度数百至上千格。矿石按深度分层（煤矿石分布在高层，钻石/红石/金矿等深入地下），并在地表下形成对应深层矿石变种。

海洋与河流的地表以上都注水到海平面（`SEA_LEVEL=62`）：河床低于海平面，所以河道里是连续的水（深约 2–6 格），只有靠近群系边界、地形被过渡带抬高的河岸列才是干的。河流的植物与树木不生成（水下不长草/花/树）。

## 运行数据

Web 版本有意不使用 `localStorage`。所有可变数据都以 JSON 文件保存在 `web/run/` 下，目录结构与 Python 项目的运行数据布局一致。

```text
run/accounts/<用户名>.json          加盐 SHA-256 账号记录
run/config/<用户名>.json            用户界面、移动参数和按键绑定
run/worlds/<用户名>.json            世界列表和每个世界的物理参数
run/worlds/<用户名>_<世界ID>.json   玩家位置、模式、方块数字 ID 表
run/worlds/<用户名>_<世界ID>.chunk.<区块X>.<区块Y>.dat   被修改区块的原始字节
```

世界 ID 使用 UUID，因此修改显示名称不会影响存档路径。存档采用"只存被修改区块"的脏区块模型：未触碰区块在进入视距时由种子重建，玩家破坏/放置只标记所在区块，自动保存仅上传脏区块。世界状态 JSON 记录玩家位置、模式与 `idTable`（数字方块 ID → 资源 ID 的映射），每个脏区块存为独立的二进制 `.dat` 文件（原始 Uint16Array 小端字节，可还原为 base64 传输）：

```json
{
  "playerX": 0,
  "playerY": 45.001,
  "mode": "creative",
  "idTable": ["my2dworld:grass_block_side", "my2dworld:dirt"]
}
```

加载时先按种子重建区块，再用 `idTable` 把存档中的数字 ID 重映射到当前插件集的方块。旧版"重建 + 差异"存档格式不再识别，直接视为全新世界。

服务端只允许文件名组件使用单词字符、连字符和下划线，以阻止路径遍历。

## 日志系统

日志遵循原 Python 项目的运行方式：每次执行 `npm run dev` 都会在 `run/logs/` 创建一个按本机启动时间命名的文件，例如 `2026-08-04_14-30-00.log`。日志同时输出到 Node 控制台和文件。

服务端会记录启动、账号初始化、登录/注册、设置保存、世界列表保存、世界存档写入与删除、插件扫描及 API 错误。浏览器会通过本地 `/api/log` 接口记录游戏开始、结束、暂停、恢复、模式切换、方块放置/破坏、虚空重生和移动速度修改。

日志仅记录事件参数，不记录明文密码。登录和注册日志仅记录用户名和结果。

## 物品栏与副手

按 `E` 打开物品栏（旁观模式不可用）：鼠标左键拿起/放下整堆，同 id 会合并到堆叠上限，不同物品则交换；关闭物品栏时手上拿着的堆叠自动归位。

**左键拖动 = 均分**：按住左键拖过多个格子再松开，鼠标上的那一堆会被**均分**到拖过的这些格子里——每格先分 `数量 ÷ 格数`，余数从前面的格子开始各多 1 个（例：64 个拖过 3 格 → 22 / 21 / 21，全部放进格子，不会剩在手上）。规则细节：

- 目标只包括**鼠标真正扫过**的格子；从某格拿起时那一格已被清空，所以它默认不算目标（把鼠标再拖回它上面就会算进去）。
- 只往**空格**或**同 id 且没满**的格子放；不同 id 的格子保持原样、不会被交换。一格放不下（半满的同 id 格）剩下的部分留在鼠标上。
- 只拖到一个格子（或在原地单击）时仍是原来的「放置 / 合并 / 交换」语义，不会两边各分一半。
- 松手时停在创造模式的红色 `×` 销毁格上会直接销毁鼠标上的那一堆。

- 面板图按模式区分：创造模式用 `public/assets/gui/creative_inventory/tab_inventory.png`，生存/冒险模式用 `public/assets/gui/container/inventory.png`。槽位坐标写在 `src/main.ts` 的 `INVENTORY_PANELS` 里（源图像素），换图后只需改这些数值。
- 创造模式物品栏右下角的红色 `×` 格是销毁格：把鼠标上的整堆放进去即销毁。
- 副手格显示在两张面板图各自的副手槽中（创造图 `(68, 38)`、生存图 `(152, 122)`），同时也会显示在 **HUD 快捷栏左侧的独立小面板**里（与快捷栏之间留 12px 空隙，鼠标悬停可看名称）。按 `F` 把副手格与当前选中的快捷栏格互换，也可以直接用鼠标在副手格里存取物品。
- 左右手的物品会绘制到玩家骨骼动画 `public/animations/player/*.myanim` 的 `itemL`（左手/副手）与 `itemR`（右手/主手）节点上；空手时不绘制。
- **单格堆叠上限按物品区分**（`stackLimit(id)`）：方块 64，工具 1。合并、拖动均分、`/give`、中键复制、掉落物合并都按各自上限处理，工具不会与别的工具合并、丢出去再捡回来也保留剩余耐久。

## 工具与物品配置

镐、斧、剑、锹、锄共 **35 件**（木/石/铜/铁/金/钻石/下界合金 × 5 类），定义写在 [`public/items/items.json`](./public/items/items.json)，贴图取自 `public/assets/items/`（文件名与 `texture` 字段一致）。服务端把它挂在 `/api/items` 上原样透传，客户端启动时（`loadItemConfigs()`）校验并写入物品注册表。

```json
{
  "items": {
    "my2dworld:iron_pickaxe": {
      "label": {"zh": "铁镐", "en": "Iron Pickaxe"},
      "texture": "iron_pickaxe",
      "tool": "pickaxe",
      "tier": "iron",
      "miningSpeed": 6,
      "damage": 4,
      "durability": 250,
      "stackSize": 1
    }
  }
}
```

| 字段 | 说明 |
| --- | --- |
| `label` | 中英文显示名（与方块一样直接写在 JSON 里） |
| `texture` | `public/assets/items/<texture>.png` 的文件名 |
| `tool` | 工具类别：`pickaxe` / `axe` / `shovel` / `hoe` / `sword` |
| `tier` | 材质等级，仅用于分组与展示 |
| `miningSpeed` | 挖掘速度倍率 |
| `damage` | 攻击伤害 |
| `durability` | 耐久上限；省略表示不消耗耐久 |
| `stackSize` | 单格堆叠上限（工具 1） |

- **挖掘速度**：方块的对口工具写在 `public/blocks/blocks.json` 的 `tool` 字段（石头/矿石/深板岩 = 镐，原木 = 斧，草方块/泥土/沙子/雪 = 锹，树叶 = 锄）。手持**类别一致**的工具才加速，否则与空手同速。耗时 = 方块硬度 / 工具速度（`core/items.ts` 的 `miningSeconds`），例如石头硬度 4 → 空手 4 秒、木镐 2 秒、石镐 1 秒、钻石镐 0.5 秒。
- **攻击伤害**：手持工具时用 `damage`（空手回落到 `public/entitiesattack.json` 的 `playerDamage`，默认 2）。剑伤害 4~8，斧 7~10。创造与生存/冒险都按手持工具结算，但只有生存/冒险模式消耗耐久。
- **耐久**：`ItemStack.durability` 记录剩余耐久（缺省=满）。生存/冒险模式每挖掉一格方块 / 命中一次生物扣 1 点，归零时工具损坏消失并提示；槽位底部显示耐久条（未满才显示），悬停提示会显示 `剩余/上限`。存档与掉落物都会保留剩余耐久。
- 改完 `items.json` 后游戏内执行 `/reload items` 即可生效（重新读取配置并刷新贴图），无需重开页面。

工具目前通过 `/give <工具ID>` 获得（如 `/give diamond_pickaxe`），与方块一样没有合成界面。ID 一览见 [`docs/zh_cn/commands_zh.md`](./docs/zh_cn/commands_zh.md)。

## 游戏速度（/tick）

`/tick` 控制客户端 tick 速率：**20 tick/秒 = 正常速度**（1 倍速）。

```text
/tick [rate <1-200|normal> | freeze [on|off] | unfreeze | step [n]] | /tick <1-200>
```

- 倍率：`40` = 2 倍速、`10` = 半速、`200` = 10 倍速、`1` = 1/20 速。生物、流体、掉落物、昼夜时刻、自动保存全部按这个倍率缩放，一整天（20 分钟）也随之缩短或拉长。
- **倍速不改变单步物理**：一帧要模拟的秒数 = 真实帧时长 × 倍率，再拆成**不超过 1/20 秒**的子步逐个模拟（`core/tick.ts` 的 `simulationSteps`），所以 10 倍速下也不会穿墙；每帧还有步数上限，避免极低帧率时陷入死亡螺旋。
- `/tick freeze` 冻结世界（只保留渲染与输入，聊天/菜单照常），配合 `/tick step [n]` 可以一帧一帧地观察生物与流体；`/tick unfreeze` 恢复。
- 速率与冻结状态只作用于当前会话，不写入存档。速率非 20 或处于冻结时，HUD 生命条右侧会显示当前 tick 状态。
- `/time cycle off` 只冻结时刻，`/tick freeze` 冻结整个世界。

## 游戏模式

四种模式，`F3` + `F4` 按 创造 → 生存 → 冒险 → 旁观 循环，也可以用 `/gamemode <模式>` 直接切换。当前模式的图标显示在画面右上角（`public/assets/gui/gamemode/*.png`），切换提示也会带图标；模式随存档保存，创建世界时可选。

| 模式 | 可飞行 | 受伤 | 破坏方块 | 放置消耗物品 | 工具耗耐久 | 挖方块掉落 |
| --- | --- | --- | --- | --- | --- | --- |
| 创造 `creative` | ✅ | 只受虚空伤害 | ✅（瞬间） | ❌（无限） | ❌ | ❌ |
| 生存 `survival` | ❌ | ✅ | ✅（有挖掘时间） | ✅ | ✅ | ✅ |
| 冒险 `adventure` | ❌ | ✅ | ❌ | ✅ | ✅ | —（挖不动） |
| 旁观 `spectator` | ❌（自由飞行视角） | ❌ | ❌ | ❌ | ❌ | ❌ |

冒险模式就是「不能破坏方块的生存模式」：按左键挖方块没有裂纹、不掉落、也不消耗耐久，但点击生物仍按手持武器结算伤害；背包、副手、丢弃与拾取都和生存模式一样。实现上 `AdventureMode` 直接继承 `SurvivalMode`，只把 `canMine` 关掉；`main.ts` 用 `survivalLike` 统一处理「生存或冒险」的差异（消耗方块、扣耐久、方块掉落自身）。

## 方块破坏与掉落

生存模式左键破坏方块时，被破坏的方块会掉落自身（掉落在原地，可以走过去捡起）。冒险模式与旁观模式不能破坏方块（见上面的[游戏模式](#游戏模式)）。

挖掘速度由「手持工具 × 方块要求的工具类别」决定（见上面的[工具与物品配置](#工具与物品配置)）：类别一致按 `miningSpeed` 加速，否则与空手同速；挖掘过程中目标格上会显示裂纹与碎屑。挖掉一格会消耗手持工具 1 点耐久（创造模式不消耗）。

花草、仙人掌这类**地物（`feature: true`）不能悬空**：破坏它们底下的方块后，地物会跟着一起被破坏，并且同样掉落自身（不会凭空消失）。级联只作用于地物——树干、树叶和普通方块不会跟着掉。这个级联与上报写在 `World.breakBlock(x, y, onBroken?)` 里，`onBroken` 会对每一格被破坏的方块回调一次，`main.ts` 据此逐格生成掉落物。

## 水与游泳（生存 / 冒险模式）

水里按 `Space` 是**上浮**（不是跳跃）：水下按住空格会以固定速度浮上来，松开则受浮力缓慢下沉，并按水流方向被推动。

**水面不是跳板**：生存/冒险模式下，脚底在水面或水面以下时按空格不会起跳——既不能站在水面上跳，也不能反复点空格一路飞上去（改动前反复点空格能升到几百格高）。想离开水面，先按住 `Space` 浮出液面（脚底高于水面），再按 `Space` 起跳即可：跳一次 + 二段跳足够爬上河边/海边的岸（实测 6~8 秒就能上岸）。创造模式不受此限制，水面照旧可以起跳。

判断依据是「玩家所在列、脚底向下 3 格内的那一串水的液面高度」：脚底在该液面或更低 → 不允许起跳；已经高于液面 → 正常起跳。跳完落回水里会重新获得跳跃次数，所以可以反复尝试，但每次的高度都有上界。

## 昼夜循环与环境光照

一个昼夜 = 现实 **20 分钟**（`src/core/daylight.ts` 的 `DAY_LENGTH_SECONDS`）。时刻从世界存档恢复，`F3` 调试面板的「时间」一行会显示当前时刻。

**天空**按当天时刻在调色板上取色（正午仍是原来的天蓝色 `#82c9d7`）：

- 白天有蓝天；日出/日落各有约 2.4 分钟（`0.1` 天）的平滑过渡，并在地平线附近叠加暖色霞光。
- 夜里天空转为深蓝，出现**星空**（70 颗固定位置、轻微闪烁的星星）与**月亮**；白天是**太阳**沿弧线东升西落。日月与星星都画在方块之前，所以会被地形自然遮挡。

**环境光照**分两部分：

- **地表以上**按当时的天空亮度照亮：正午 `1.0`、午夜 `0.18`（不会全黑，仍能看清轮廓）。
- **地表以下**（更准确地说，某列**最高非空气方块**以下）越深越暗，过渡带 `SHADOW_DEPTH = 6` 格，再往下固定为洞穴亮度 `0.14`（压暗约 86%）。所以**洞穴、深水、树荫下面都会变暗**，而水面本身是亮的、水下逐格变暗。
- 明暗分界按列缓存（`World.columnTop(x)`），放置/破坏方块或区块卸载时自动失效，所以挖洞、搭塔后光照立刻跟上。
- 生物、玩家与掉落物也会按各自所处深度压暗；粒子保持不变。

在 `Esc` → `设置` 里有两行相关开关：

- **昼夜循环**：关闭后时刻冻结（天空与光照停在当前时刻，适合安心建筑）。
- **环境光照**：`关闭 / 50% / 75% / 100%`（默认 100%）；调到「关闭」则全世界全亮。

指令 `/time` 可以查看/设置时刻、开关循环，详见 [`docs/zh_cn/commands_zh.md`](./docs/zh_cn/commands_zh.md)。

## 聊天命令

只有以 `/` 开头的输入会作为命令解析，普通输入会显示为聊天消息。

```text
/gamemode creative | survival | adventure | spectator
/speed <数值>      # /movespeed <数值> 同义
/debug on | off
/seed              # 查看当前世界种子
/locate <群系>     # 定位最近的群系并传送
/tp <x> [y]        # 传送到指定坐标
/summon <实体> [x] [y]   # 召唤一只不会因距离消失的怪物
/aggro <数值>      # 设置生物仇恨距离（1–128，默认 24，持久保存）
/time [set <0-24|day|noon|night|midnight|sunrise|sunset> | add <小时> | cycle on|off]
/tick [rate <1-200|normal> | freeze [on|off] | unfreeze | step [n]]   # 游戏速度（20 tick/s = 正常）
/give [<目标>] <方块|物品> [数量]   # 含工具（如 /give diamond_pickaxe）
/structure export|load|list|delete   # 自定义结构导入/导出
/reload [images | items | animations | hitboxes | squeeze | plugins | all]
```

`/reload` 就地刷新资源与配置，无需重新加载页面：`images` 重新请求方块/物品/GUI/角色贴图（带缓存爆破），`items` 重新读取 `public/items/items.json` 并刷新物品贴图，`animations` 重新拉取 `public/animations` 清单，`hitboxes` 重新加载 `public/hitboxes` 配置并刷新已有实体碰撞箱，`plugins` 卸载并重新安装全部插件。省略目标时等于 `all`。聊天输入框是真实 DOM 输入框，支持选中、复制/粘贴与中文输入法；输入的命令带语法高亮（命令金色、子命令绿色、数字蓝色），长命令自动换行且输入框随之增高，命令提示块可悬停（变黄）或点击补全。

创建世界时可以填写种子（留空则自动生成）：同一种子总是生成相同地形，可用于复现或分享世界。世界列表和 F3 调试面板会显示当前世界的种子，`/seed` 命令可在游戏内查看。

聊天行为与 Python 版一致：`Tab` 循环补全命令或参数，`ArrowUp` 和 `ArrowDown` 浏览已提交输入历史，聊天框打开时可用滚轮（或 `PageUp`/`PageDown`）浏览消息记录。

`/speed` 会更新当前玩家、当前世界的 `physics.walkSpeed` 以及用户默认移动设置，并写入对应运行数据文件。因此重新进入世界后仍会保留命令设定的速度。`/aggro` 同理，会把仇恨距离写入用户设置并持久保存；也可在暂停菜单「显示样式」中调整聊天/命令字体大小。

## 渲染说明

全部源美术资源已从 `py/image/` 和 `py/fonts/` 迁移。

- Canvas 图像平滑已关闭。
- 方块绘制位置和缩放尺寸会取整到像素。
- **方块 / 流体 / 压暗带的屏幕矩形会对齐到设备像素**（`src/core/pixels.ts` 的 `snapToDevice` / `deviceSpanSize`）：
  相邻两格用同一个表达式算共享边，所以边都正好落在物理像素边界上。这一步专门修掉了「在海洋里移动时画面出现水平
  白色横线」——`devicePixelRatio` 不是整数时（Windows 125%/150% 缩放 → 1.25/1.5），整数 CSS 坐标会落在半个物理
  像素上，两块相邻的半透明水各自按覆盖率抗锯齿，交界像素的合成 alpha 比设定值低（最多低 18%），天空就从缝里透出来；
  摄像机移动时这个相位一直在 0/0.25/0.5/0.75 之间扫动，所以白线是**移动时才出现**、并且一格一条（32px 一格）。
  `dpr` 为整数时这些函数是恒等变换，与旧版渲染逐像素一致。
- 方块严格按一个方块尺寸绘制，不重叠覆盖。
- 方块破坏粒子从被破坏方块的真实纹理中随机裁切，不使用生成颜色。
- 玩家碰撞盒保持为 `0.5 x 1.9` 世界方块；原始正方形角色贴图以更宽的视觉尺寸绘制，避免人物看起来被压扁。
- 怪物碰撞箱可配置：默认值在 `src/core/entity.ts` 的 `MOB_KINDS`，可用 `public/hitboxes/` 下的分类 JSON 覆盖——`cow`/`cow_baby`/`pig`/`pig_baby`/`zombie`/`zombie_baby` 分别覆盖大牛/小牛/大猪/小猪/大僵尸/小僵尸（如 `cow.json` 同时作用于所有成年牛与哞菇；僵尸/尸壳/溺尸共用 `zombie.json`），也可写 `<kind>.json` 只覆盖单个 kind（精确 kind 优先于分类）。插件运行时可用 `api.registerHitbox()` / `api.setHitboxes()` 覆盖（插件优先级最高，key 同样支持分类名）。省略 `centerY` 时默认 `height/2`（脚底锚定），物理碰撞、点击/范围判定与可视化共用同一碰撞箱。`F3` 旁的碰撞箱/范围键（默认见键位设置）可开关碰撞箱与破坏范围可视化。

原始纹理许可证保留在 `public/assets/LICENSE.txt`。

## 扩展开发

新增方块时：

1. 本体方块在 `public/assets/block/` 下添加 PNG 纹理；插件方块将 PNG 放在自己的 `plugins/<插件ID>/assets/` 下，并使用 `api.asset()` 引用。
2. 本体内容在 `src/i18n.ts` 中添加中英文显示名称；插件方块直接在 `label` 中提供名称。
3. 插件拥有的内容通过 `PluginRegistry.registerBlock()` 注册。使用本体内容时引用 `api.Blocks.MY2DWORLD.STONE`，使用自身内容时引用 `api.Blocks.<PLUGIN_ID>.MY_BLOCK` 或注册结果的 `.id`。
4. 只有需要默认出现的方块才加入地形生成或快捷栏逻辑。

新增物品/工具时：

1. 把 PNG 放进 `public/assets/items/`，文件名与配置里的 `texture` 一致。
2. 在 `public/items/items.json` 的 `items` 里加一条：`label`（中英文）、`texture`、`tool`、`tier`、`miningSpeed`、`damage`、`durability`、`stackSize`。
3. 想让某个方块被这类工具加速，给 `public/blocks/blocks.json` 里那个方块加 `tool` 字段（`pickaxe`/`axe`/`shovel`/`hoe`/`sword`）。
4. 游戏内 `/reload items` 生效，`/give <物品ID>` 拿取；挖掘耗时与伤害公式只在 `src/core/items.ts` 里，不要在别处再写一份。

新增游戏模式时：
1. 在 `src/modes/` 中新增 `GameMode` 实现（与某个已有模式只差一两条规则时，直接继承它并覆写开关，例如 `adventure.ts` 就是 `canMine = false` 的生存模式）。
2. 更新 `createMode()`，并在 `src/core/registry.ts` 的 `gameModeRegistry.register({id, label})` 注册、`src/core/types.ts` 的 `GameModeName` 加上名字。
3. 在 `i18n.ts` 中添加本地化模式名称（`mode_<id>` 与 `world_mode_<id>`）。
4. 图标放进 `public/assets/gui/gamemode/<id>.png`，并加入 `main.ts` 的 `MODE_ICON_SOURCES`（HUD 右上角与切换提示自动使用，`/gamemode` 的可选值也取自这张表）。
5. 如果该模式与生存模式共享「受伤 / 不飞行 / 放置消耗方块 / 工具耗耐久 / 方块掉落自身」中的任意几条，用 `main.ts` 的 `survivalLike` 判定，不要在各处再写一遍模式字符串比较。
6. 服务端存档白名单（`server.mjs` 的 `/api/world-save`）也要加上新模式 id，否则存盘时会被改写回 `creative`。
7. 游戏状态放在模式对象或 `core/` 中，不应放入 DOM 事件处理器。

调整怪物碰撞箱时：

1. 内置默认值在 `src/core/entity.ts` 的 `MOB_KINDS`。
2. 想不改代码覆盖：在 `public/hitboxes/<分类>.json` 写入 `{ "halfWidth": 0.3, "height": 0.8, "centerX": 0, "centerY": 0.2 }`，分类为 `cow`/`cow_baby`/`pig`/`pig_baby`/`zombie`/`zombie_baby`（大/小 × 牛/猪/僵尸），游戏内用 `/reload hitboxes` 生效；写 `<kind>.json` 可只覆盖单个 kind（精确 kind 优先于分类）。
3. 插件运行时用 `api.registerHitbox(kind, config)` 或 `api.setHitboxes({...})` 覆盖，优先级高于文件配置；`/reload plugins` 会清空插件覆盖。

物理挤压已与碰撞箱**彻底分离**（三份独立配置：碰撞箱几何 / 挤压箱几何 / 挤压参数）：

4. 碰撞箱：`public/hitboxes/<分类>.json`（或 `<kind>.json`），审定体积/重叠/推开。
5. 挤压箱几何：`public/squeeze/<分类>.json`（或 `<kind>.json`），**结构与碰撞箱一致**（`halfWidth`/`height`/`centerX`/`centerY`/`boxes`/`left`/`right`），决定挤压重叠检测的盒体与阈值参考尺寸；内置默认文件是「碰撞箱缩小一圈」（半宽/高度各 `-0.1`、中心不变），未配置时同样自动缩小回退——**挤压伤害只按挤压箱结算，绝不退化成按碰撞箱结算**（玩家侧的挤压箱也是身体缩小一圈）。游戏内 `/reload squeeze` 生效。
6. 挤压参数：`run/config/squeeze.json`（全局一份，对任意生物生效），含 `baseDamage`、`thresholdRatio`、`iframe`、`maxDamage`、`difficulty`、`playerDamageScale`。首次启动服务器会自动写入默认值；游戏内 `/reload squeeze` 生效。

碰撞箱与挤压箱都支持**多矩形并集**与**左右朝向**：JSON 里可用 `boxes`（多矩形数组）拼出多边形体积，用 `left`/`right` 分别为面朝左/右配置矩形；未写 `left` 时面朝左自动水平镜像。详细字段与示例见 [`docs/zh_cn/entity_config_zh.md`](./docs/zh_cn/entity_config_zh.md)。

注册插件动画时（覆盖某个动物家族所有 kind 的动画）：

```ts
await api.registerAnimation("cow", "walk", api.asset("animations/cow.walk.myanim"));
```

家族为 `player | zombie | cow | pig`，姿态为 `idle | walk | attack`。`.myanim` 格式与 `public/animations` 下的内置文件相同；相对图片路径相对动画文件所在目录解析。

插件 API、自动加载约定、生命周期和当前限制见 [插件开发文档](./docs/plugin-development-zh.md)。

## 当前范围

当前版本覆盖 Python 项目的主动玩家和世界流程，并引入了实体系统：

- **程序化地形与区块流送**：无限横向世界，`Y=-64` 基岩到 `Y=320` 建造上限，七个群系（海洋/河流/平原/森林/沙漠/雪原/山地，多尺度生成：海洋 5000+ 格、河流 50–100 格、气候带数百至上千格）、树木、仙人掌、岩石与多种矿石（含深层变种）。
- **玩家系统**：物理、碰撞、二段跳、飞行、创造/生存/冒险/旁观四种模式、方块破坏与放置、纹理粒子、灵魂出窍（`F7`）；身体被实心方块挤压（窒息）时每 0.5s 受 1 点伤害。
- **工具与物品**：镐/斧/剑/锹/锄共 35 件（7 种材质 × 5 类），贴图取自 `public/assets/items/`，挖掘速度、攻击伤害、耐久与堆叠上限全部由 `public/items/items.json` 配置；对口工具才加速挖掘，生存/冒险模式挖方块/打生物消耗耐久。
- **游戏速度**：`/tick` 调整 tick 速率（20 tick/秒 = 正常速度，1~200 可调），并可冻结世界、单步推进观察。
- **实体系统**：按群系刷新的僵尸/僵尸猪/奶牛等 Mob，含 AI（索敌、追击、攻击）、`/summon` 持久召唤、可配置碰撞箱与 `.myanim` 动画文件；生物与生物之间互相碰撞推挤（防止堆怪），被方块挤压也会窒息受伤。
- **交互反馈**：鼠标悬停生物时显示攻击光标（`assets/gui/mouse/attack.png`）并在方块之上高亮该生物；主界面背景从 `assets/Homepage_background/` 中随机选取。
- **持久化**：账号、设置、世界列表、只存脏区块的世界存档、日志文件。
- **扩展**：插件系统（方块、游戏事件、消息、动画、碰撞箱）、聊天命令、菜单、中英文界面。
- 未来背包系统尚未接入运行循环，但相关纹理已包含在 `public/assets/entity/` 中。
